# Optimization roadmap

路线图只保留尚未完成、能明确验收的工作。已完成历史统一放在 `CHANGELOG.md`。

## 近期：稳定发布

- 完成实体手机、真实手柄、音频和十房连续通关。
- 每次发布确认 Pages 构建号、CSP、SDK 加载和云存档入口。
- 收集公开试玩反馈，只修复可复现问题，不增加房间。

## 中期：低风险模块化

纯函数、只读房间数据、存档规则、输入映射、训练状态与第一组 UI 展示模型已经完成拆分。下一步按 `docs/ARCHITECTURE.md` 继续处理有直接消费者的无副作用 UI 展示模型；每次只移动一个领域，保持玩法、存档 schema 和 DOM 不变。物理与渲染必须等十房人工基线完成后再动。

完成标准：

- 新模块有明确导入方；
- 不保留重复常量或兼容脚手架；
- `npm run check` 与 `npm run browser-smoke` 通过；
- 对应改动可由单个提交回滚。

## 后期：系统拆分

依次处理存档、输入、训练、UI、物理和渲染。物理/渲染拆分前必须先建立更细的可重复回放或确定性模拟测试，并完成一次十房人工基线记录。

## 暂不做

- 新房间、排行榜或第二套成就系统；
- 为“看起来模块化”创建空目录；
- 未被运行时消费的适配层；
- 在同一发布中引入构建器并重写核心玩法；
- 通过降低玩法复杂度掩盖性能问题。
