# 界面设计约定

## 方向：月夜山景里的攀登入口

山景是主角。首屏与主菜单共用无外框的启动构图：英文小标、暖金游戏标题、一个金色主操作、雾青次操作。首次选择仅补充“选择游玩方式”和本地/云端存档说明，不再出现独立的后台式白色选择框，不使用无语义的 S 图标。

账号表单是独立任务，使用一张浅色面板；设置与练习继续按需展开。保留浅色网页环境、桌面宽度上限、原小人和固定发色，不修改地图、镜头和玩法渲染。

## 布局与状态

- 启动界面共用 `.launch-surface`，标题与按钮样式只有一个最终定义。金色表示开始，雾青表示次级入口；焦点环独立保留，不以取消键盘可见性换取简洁。
- 桌面菜单以游戏容器宽度（cqw）定比例，不随浏览器留白盲目变大：主按钮宽 300–400px，标题 48–76px；手机按钮仍上限 320px。设置面板宽 440px，单张雾色纸面内使用细分隔线/17px 线性图标，反馈与存档另留 16px 分组间距。
- 滑块旁显示百分比或触控像素，首次载入、输入变化及重新打开时同步数值与 `aria-valuetext`，不改动设置取值与存档结构。
- 仅启动遮罩加入边缘柔和的中心暗化，防止平台亮边穿过标题；实际游玩与结算不受影响。
- 账号页桌面宽 430px，标题和表单共用 28px 左边线，左右等距；滚动条只在需要滚动时出现，避免空槽令内容偏左。窄屏保留安全区，表单内部滚动，关闭键始终可达。
- 表单字段与按钮不小于 44px，标签/说明至少 12px，标签至输入框 7px，字段组之间 16px。说明自然换行，底部状态只用一条分隔线。
- 错误为深红、成功为深绿，并保留明确文字；普通文字样式不得覆盖状态语义。
- 登录模式切换、返回入口、真实错误长文案、首次进入、刷新、横竖屏和软键盘高度变化都属于设计验收，不只验收默认截图。

## 验证与维护

在本地浏览器实际查看入口、主菜单、账号验证码/密码、设置和练习。浏览器门禁验证启动页同源样式、账号左右留白、内层透明、提示颜色、窄屏可达与无溢出。自动门禁不替代构图判断；实体手机触感仍需真人验证。

维护 `summit-spark.css` 中 P308 组件区，不再为每次版本追加同组件补丁。其余历史 UI 样式分阶段整理，避免一次性重写影响游戏中的 HUD。
